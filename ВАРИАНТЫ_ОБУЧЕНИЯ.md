# Варианты системы обучения для классификации расходов

## Цель

Система должна "учиться" на примерах пользователя, чтобы со временем автоматически определять категорию расхода с высокой точностью.

---

## Вариант 1: Ручное добавление правил через интерфейс

### Описание

Пользователь вручную добавляет новые правила классификации через веб-интерфейс.

### Как работает

1. Пользователь вводит расход: "Бетон"
2. Система не может определить категорию → показывает список категорий
3. Пользователь выбирает "Мат"
4. Система предлагает: "Создать правило для 'Бетон' → 'Мат'?"
5. Если пользователь подтверждает → правило добавляется в `expense_classification_rules`

### Преимущества

✅ Полный контроль пользователя  
✅ Правила добавляются явно и понятно  
✅ Легко удалить/изменить неправильное правило  
✅ Простота реализации

### Недостатки

❌ Требует ручного действия пользователя каждый раз  
❌ Если пользователь забыл создать правило, система не запомнит выбор

---

## Вариант 2: Автоматическое запоминание выбора

### Описание

Система автоматически запоминает выбор пользователя и создаёт правила на основе статистики.

### Как работает

1. Пользователь вводит расход: "Бетон"
2. Система не может определить категорию → показывает список категорий
3. Пользователь выбирает "Мат"
4. Система **автоматически** создаёт правило: `('keyword', 'Бетон', 'Мат')`
5. При следующем вводе "Бетон" система сразу определит "Мат"

### Дополнительные возможности

- Если пользователь **3 раза подряд** выбрал одну и ту же категорию для одной и той же фразы → правило становится "постоянным"
- Если пользователь выбрал другую категорию → старое правило удаляется/обновляется

### Преимущества

✅ Минимум действий от пользователя  
✅ Система учится автоматически  
✅ Чем больше используется, тем точнее

### Недостатки

❌ Может создать "шум" (неправильные правила при ошибках)  
❌ Нужен механизм очистки неправильных правил  
❌ Требует больше логики в коде

---

## Вариант 3: Анализ CSV и создание правил (полуавтоматический)

### Описание

Система анализирует существующие CSV файлы и предлагает создать правила на основе уже существующих данных.

### Как работает

1. Пользователь загружает CSV файл с расходами
2. Система анализирует:
   - Какие слова/фразы чаще всего встречаются в категории "Мат"
   - Какие слова/фразы чаще всего встречаются в категории "ФОТ"
   - И т.д.
3. Система показывает список предлагаемых правил:
   ```
   Предложенные правила:
   - "Бетон" → Мат (встречается 5 раз)
   - "Штукатурка" → Мат (встречается 12 раз)
   - "Грунт" → Мат (встречается 8 раз)
   ```
4. Пользователь выбирает, какие правила применить

### Преимущества

✅ Использует уже существующие данные  
✅ Может создать много правил сразу  
✅ Пользователь видит статистику перед применением

### Недостатки

❌ Требует загрузки CSV (одноразовое действие)  
❌ Нужен парсер CSV  
❌ Может предложить нерелевантные правила

---

## Вариант 4: Комбинированный (рекомендуемый)

### Описание

Сочетание вариантов 1, 2 и 3.

### Как работает

**Этап 1: Начальная настройка (одноразово)**
- Загрузка CSV → анализ → предложение правил (Вариант 3)

**Этап 2: Ежедневное использование**
- Автоматическое запоминание выбора (Вариант 2)
- При необходимости ручное добавление правил (Вариант 1)

**Этап 3: Управление правилами**
- Веб-интерфейс для просмотра/редактирования/удаления правил
- Статистика применения правил (сколько раз правило сработало)
- Возможность временно отключить правило (`is_active = FALSE`)

### Преимущества

✅ Гибкость  
✅ Автоматизация + контроль  
✅ Можно начать с CSV, потом доучиваться на практике

### Недостатки

❌ Самый сложный в реализации  
❌ Требует больше кода

---

## Предложение реализации

### Минимальный вариант (для начала):

**Вариант 2** (автоматическое запоминание) + интерфейс просмотра правил

- Когда пользователь выбирает категорию вручную → создаём правило автоматически
- В настройках системы → список всех правил с возможностью удалить неправильное

### Расширенный вариант (позже):

**Вариант 4** (комбинированный)

- Добавить загрузку CSV для начального обучения
- Добавить статистику применения правил
- Добавить возможность группировки правил (например, все правила для "Мат")

---

## Техническая реализация

### Таблица для статистики (опционально)

```sql
CREATE TABLE taiga.expense_classification_statistics (
    id SERIAL PRIMARY KEY,
    rule_id INTEGER REFERENCES taiga.expense_classification_rules(id),
    times_applied INTEGER DEFAULT 0,
    last_applied TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### API Endpoints

- `POST /api/expenses/classify` - определение категории
- `POST /api/classification-rules` - создание правила вручную
- `GET /api/classification-rules` - список всех правил
- `PUT /api/classification-rules/:id` - обновление правила
- `DELETE /api/classification-rules/:id` - удаление правила

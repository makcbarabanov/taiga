# 🎓 Система обучения классификации расходов

## 📋 Процесс обучения

### Этап 1: Получение чека с расходами
- Пользователь отправляет "чек" с расходами (текст, список позиций)
- Система получает список расходов для классификации

### Этап 2: Определение категорий
- Система анализирует каждую позицию расхода
- Использует существующие правила из `expense_classification_rules`
- Определяет предполагаемую категорию для каждой позиции

### Этап 3: Уточнение у пользователя
- **Система задаёт вопросы по одному** (не все сразу)
- Каждый вопрос имеет счётчик в формате **1/n** (где 1 - номер текущего вопроса, n - общее количество вопросов)
- Система спрашивает: "Правильно ли определена категория?"
- Пользователь подтверждает или исправляет категорию
- **После подтверждения** система переходит к следующему вопросу
- **При малейшем сомнении** система задаёт уточняющие вопросы
- Обсуждение происходит последовательно, пока не будет достигнуто 100% подтверждение всех расходов
- **ВАЖНО: Вносить изменения в БД только после ответов на все вопросы, а не после каждого ответа**

### Этап 4: Совершенствование правил
- При обнаружении ошибки или нового случая система:
  - Анализирует, почему была ошибка
  - Создаёт новое правило или обновляет существующее
  - Сохраняет правило в `expense_classification_rules` для будущего использования
- **При появлении нового паттерна его нужно записать в систему обучения**, чтобы в дальнейшем система сама без помощи и подсказки безошибочно определяла расходы

### Этап 5: Добавление расходов в Админку
- После достижения **100% подтверждения** всех расходов от пользователя
- Система автоматически добавляет все расходы в Админку (таблица `expenses`)
- Каждый расход сохраняется с подтверждённой категорией и всеми данными

### Этап 6: Критерий завершения обучения
- Обучение считается завершённым, когда система **3 раза подряд** определяет все расходы на **100%** без ошибок
- После этого система может работать автоматически

---

## 🎯 Принципы обучения

1. **Активное уточнение:** При малейшем сомнении система задаёт вопросы
2. **Накопление правил:** Каждое новое правило сохраняется для будущего использования
3. **Приоритет точности:** Лучше спросить, чем ошибиться
4. **Итеративное улучшение:** Система учится на каждой ошибке

## 📝 Пример процесса обучения

### Пример 1: Успешное определение

```
Пользователь: "Бетон М300, 2 куба"
Система: "Определяю категорию: Материалы (Мат). Правильно?"
Пользователь: "Да"
Система: "✅ Правило сохранено. При следующем упоминании 'Бетон' категория будет определена автоматически."
```

### Пример 2: Исправление ошибки

```
Пользователь: "Бензин для генератора"
Система: "Определяю категорию: Накладные (по слову 'Бензин'). Правильно?"
Пользователь: "Нет, это ТЗР"
Система: "❌ Исправляю. Создаю правило: 'Бензин для генератора' → ТЗР"
```

### Пример 3: Уточняющий вопрос

```
Пользователь: "Макс"
Система: "⚠️ Сомневаюсь. Это может быть:
  - ФОТ (зарплата за работу)
  - Маржа (личные деньги)
  
Уточните, пожалуйста: это зарплата или личные деньги?"
Пользователь: "Маржа"
Система: "✅ Создаю правило: 'Макс' → Маржа (требует комментарий)"
```

## 🔧 Техническая реализация

### API Endpoints

- `GET /api/expense-classification/classify?text=...` - определение категории
- `POST /api/expense-classification/learn` - создание нового правила на основе выбора пользователя
- `GET /api/expense-classification/rules` - просмотр всех правил
- `DELETE /api/expense-classification/rules/:id` - удаление правила

### Структура данных

Правила хранятся в таблице `expense_classification_rules`:
- `rule_type` - тип правила (keyword, employee, material_pattern, pattern)
- `pattern` - паттерн для сопоставления
- `category_id` - ID категории
- `priority` - приоритет правила (больше = выше)
- `requires_comment` - требуется ли комментарий
- `description` - описание правила

## 📊 Отслеживание прогресса обучения

### Метрики успешности

- Количество правильных определений подряд
- Процент правильных определений за сессию
- Количество созданных правил
- Количество уточняющих вопросов

### Критерий завершения

**Обучение завершено**, когда:
- ✅ 3 раза подряд все расходы определены на 100%
- ✅ Нет ошибок классификации
- ✅ Система не задаёт уточняющих вопросов
